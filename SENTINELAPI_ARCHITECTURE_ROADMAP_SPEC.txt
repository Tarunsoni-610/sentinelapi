1. EXECUTIVE SUMMARY & SOLUTION VISION
================================================================================
SentinelAPI is an enterprise-grade autonomous API security platform that unifies:
1. Contract-driven OpenAPI specification ingestion and route mapping.
2. Stateful multi-session red-teaming across simulated attacker/victim personas.
3. Context-aware Generative AI patch synthesis producing ready-to-merge Unified
   Git Diffs via Google Gemini 2.5 Flash.
4. Real-time closed-loop sandbox verification proving exploit mitigation without
   introducing breaking regressions.
5. Dynamic streaming audit logging to immutable text transcripts for compliance.

By bridging automated threat discovery with verified code patching, SentinelAPI
eliminates multi-week manual security triage and reduces Mean Time to Remediation
(MTTR) from days to seconds with 0% false positives.


================================================================================
2. CORE PROBLEM STATEMENT & DEFENSE GAPS
================================================================================
Modern microservices and distributed REST APIs suffer from critical blind spots:

A. SILENT BUSINESS LOGIC FLAWS (OWASP API1: BOLA / IDOR):
   - Static Application Security Testing (SAST) linters analyze syntax, not
     runtime authorization boundaries.
   - Code that passes all unit tests and compiles cleanly can still allow any
     authenticated user to access arbitrary tenant records across boundaries.

B. FALSE POSITIVE ALERT FATIGUE:
   - Traditional Dynamic Application Security Testing (DAST) scanners flood
     developers with hundreds of theoretical warnings without actionable HTTP
     evidence payloads or reproduction steps.

C. THE REMEDIATION CHOKEPOINT (PDF FATIGUE):
   - Traditional penetration tests result in 50-page static PDF reports
     describing generic remediation concepts rather than syntax-checked,
     repository-specific code patches.

D. LACK OF VERIFICATION & REGRESSION TESTING:
   - Security teams lack automated verification pipelines to immediately prove
     that a committed code patch genuinely resolved the vulnerability without
     disrupting legitimate API operations.

4. END-TO-END WORKING WORKFLOW (PHASE 1 TO PHASE 6)
================================================================================

[Phase 1: Contract Ingestion & Discovery]
  1. Ingests OpenAPI 3.0 YAML/JSON specification.
  2. Traverses internal schema definitions, resolving all $ref models.
  3. Extracts endpoints, HTTP methods, route parameters, request bodies, and
     declared authentication schemes.
  4. Scans local source directory to associate route endpoints with concrete
     JavaScript route files and handler functions.

[Phase 2: Stateful Red-Teaming Probing]
  1. Authenticates as Victim Persona (Alice) via POST /api/auth/login.
  2. Captures Alice session state, JWT token, and private resources (Order #1001).
  3. Authenticates as Attacker Persona (Bob) to acquire Bob's valid JWT token.
  4. Dispatches cross-tenant requests (e.g., Bob requests GET /api/orders/1001).
  5. Probes public routes for PII leakage (GET /api/users/me).
  6. Probes administrative routes for missing RBAC guards (GET /api/admin/stats).
  7. Transmits high-frequency concurrent bursts (15 requests in <1s) against
     authentication handlers to evaluate rate-limiting controls.

[Phase 3: Control Invariant Validation (0% False Positives)]
  1. Evaluates non-vulnerable baseline endpoints (e.g., GET /api/invoices/{id}).
  2. Confirms that cross-tenant read attempts properly return HTTP 404/403.
  3. Evaluates catalog rate limiters (GET /api/products) to confirm HTTP 429 is
     returned during bursts.
  4. Correlates vulnerable outcomes against passed controls to guarantee zero
     false positives.

[Phase 4: Threat Intelligence & CVSS Scoring]
  1. Maps confirmed vulnerabilities to MITRE CWE IDs (CWE-639, CWE-200, etc.).
  2. Computes numerical CVSS v3.1 base scores and generates vector strings.
  3. Formulates technical root-cause analyses and compliance business impact.
  4. Generates step-by-step reproduction instructions and executable cURL PoCs.

[Phase 5: Context-Aware AI Patch Synthesis]
  1. Ingests vulnerability metadata, AST route source code, and live HTTP proof.
  2. Prompts Gemini 2.5 Flash in Structured Output mode for remediation diffs.
  3. Falls back to deterministic AST rule templates if offline or rate-limited.
  4. Validates that the generated patch is a syntactically valid Unified Git Diff.

[Phase 6: Closed-Loop Sandbox Verification & Logging]
  1. Injects the synthesized patch into the target sandbox's in-memory router.
  2. Re-executes the original exploit probe to confirm HTTP 403 / 429 resolution.
  3. Re-probes as the legitimate resource owner (Alice) to ensure HTTP 200 access
     is preserved (regression safety check).
  4. Transitions finding state from VULNERABLE -> FIX_VERIFIED.
  5. Streams full audit transcript to disk via SessionRecorder.

================================================================================
SentinelAPI features four distinct, domain-specialized agent personas:

1. OWASP TOP 10 SECURITY AUDITOR (`owasp_auditor`):
   - Badge: [AUDITOR] | Theme: #43f283 (Emerald Green)
   - Scope: Audits API contracts and endpoints against OWASP API1:2023 through
     API10:2023. Calculates CVSS v3.1 scores, assigns CWE categories, and evaluates
     overall security posture.
   - Persona Prompting: Formal, thorough, compliance-centric, and risk-oriented.

2. SECURE API INTEGRATION SPECIALIST (`secure_integrator`):
   - Badge: [INTEGRATE] | Theme: #38bdf8 (Sky Blue)
   - Scope: Specializes in secure architecture, authentication protocols (OAuth2,
     JWT, mTLS), API gateway routing, DTO data projection models, and token
     validation middleware.
   - Persona Prompting: Architectural, constructive, defensive, and best-practice.

3. AUTOMATED REMEDIATION COPILOT (`remediation_copilot`):
   - Badge: [REMEDIATE] | Theme: #c084fc (Purple)
   - Scope: Generates drop-in Unified Git Diffs and production-ready Express
     middlewares. Ensures patches are surgical, idiomatic, and introduce zero
     regression into existing workflows.
   - Persona Prompting: Developer-first, code-heavy, practical, and precise.

4. OFFENSIVE RED TEAM PENTESTER (`pentester`):
   - Badge: [PENTESTER] | Theme: #f87171 (Crimson Red)
   - Scope: Simulates aggressive threat actor tactics. Constructs weaponized
     payloads, token fuzzing sequences, high-concurrency burst bursts, and
     reproducible cURL Proof-of-Concepts.
   - Persona Prompting: Adversarial, direct, exploit-focused, and skeptical.

6. STATEFUL ATTACK PROBING ENGINE & BASELINE INVARIANT CONTROLS
================================================================================

[ATTACK MODULE 1: API1:2023 - Broken Object Level Authorization (BOLA)]
- Target Route: GET /api/orders/{id}
- CWE Mapping:  CWE-639: Authorization Bypass Through User-Controlled Key
- CVSS Score:   9.1 (Critical) | CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:N
- Probe Logic:  1. Victim (Alice) creates Order #1001.
                2. Attacker (Bob) authenticates to obtain Bob's Bearer JWT.
                3. Bob issues GET /api/orders/1001 with Bob's token.
                4. Flaw verified if server returns HTTP 200 with Alice's payload.

[ATTACK MODULE 2: API3:2023 - Broken Object Property Level Authorization]
- Target Route: GET /api/users/me
- CWE Mapping:  CWE-200: Exposure of Sensitive Information to Unauthorized Actor
- CVSS Score:   7.5 (High) | CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N
- Probe Logic:  1. Authenticates as Alice and requests /api/users/me.
                2. Compares JSON keys against OpenAPI spec response properties.
                3. Flags if leaked keys include: passwordHash, ssn, apiKey, notes.

[ATTACK MODULE 3: API2:2023 / API5:2023 - Broken Function Level Authorization]
- Target Route: GET /api/admin/stats
- CWE Mapping:  CWE-306: Missing Authentication for Critical Function
- CVSS Score:   9.8 (Critical) | CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H
- Probe Logic:  1. Sends unauthenticated anonymous GET request to /api/admin/stats.
                2. Flaw verified if server returns HTTP 200 containing tenant
                   metrics, totalOrders, and user directory.

[ATTACK MODULE 4: API4:2023 - Unrestricted Resource Consumption]
- Target Route: POST /api/auth/login
- CWE Mapping:  CWE-799: Improper Control of Generation Rate
- CVSS Score:   5.3 (Medium) | CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:L
- Probe Logic:  1. Dispatches 15 rapid concurrent POST requests in < 1 second.
                2. Flaw verified if 0 requests return HTTP 429 Too Many Requests.

[EVALUATED BASELINE CONTROLS (0% FALSE POSITIVES)]
1. Invoice Tenant Boundary: GET /api/invoices/{id} confirms Bob is rejected with
   HTTP 404/403 when requesting Alice's invoice.
2. Scoped Orders List: GET /api/orders confirms user only receives owned orders.
3. Credential Verification: POST /api/auth/login confirms invalid password returns
   HTTP 401 Unauthorized.
4. Product Catalog Limiter: GET /api/products confirms scraping bursts trigger
   HTTP 429 Too Many Requests.

8. CONTEXT-AWARE AI REMEDIATION & AST DIFF SYNTHESIS
================================================================================
The AI remediation engine employs a dual-tier strategy:

TIER 1: LLM SYNTHESIS (GEMINI 2.5 FLASH):
- Prompts Gemini with:
  1. Vulnerability description, OWASP classification, and reproduction steps.
  2. Target route specification from OpenAPI contract.
  3. AST code snippet and line references from local workspace.
  4. Live request/response evidence payloads.
- Constrains model with strict JSON Schema output to ensure generated code
  strictly conforms to the Unified Git Diff standard.

TIER 2: DETERMINISTIC AST HEURISTIC FALLBACK:
- If offline, network-isolated, or during API rate limits, the engine executes
  deterministic AST replacement templates.
- Generates verified patches immediately with zero latency.

Sample Synthesized Git Diff (BOLA Fix):
```diff
--- a/src/routes/orders.js
+++ b/src/routes/orders.js
@@ -32,7 +32,9 @@
 function getOrder(req, res) {
   const order = store.orders.find((o) => o.id === parseIntParam(req.params.id));
   if (!order) return res.status(404).json({ error: 'order_not_found' });
+  if (order.userId !== req.user.id) {
+    return res.status(403).json({ error: 'forbidden' });
+  }
   return res.json(order);
 }
```

9. CLOSED-LOOP SANDBOX VERIFICATION & REGRESSION TESTING
================================================================================
Closed-loop verification guarantees patch efficacy before merging:

State Lifecycle:
  [VULNERABLE]  ──>  [PATCH_INJECTION]  ──>  [FIX_VERIFIED]
  (Score: 10/100)                             (Score: 40/100)

Verification Rules:
1. EXPLOIT MITIGATION: Re-running Attacker Bob's probe against the patched
   endpoint must return HTTP 403 Forbidden (or HTTP 429 for rate-limiters).
2. REGRESSION SAFETY: Re-running Legitimate Owner Alice's request against the
   patched endpoint must return HTTP 200 OK with valid data.
3. INVARIANT INTEGRITY: All existing baseline controls must continue to pass.

10. DYNAMIC REAL-TIME SESSION RECORDING (SESSIONRECORDER)
================================================================================
The `SessionRecorder` class (`cli/src/sessionRecorder.js`) manages live audit
logging for every agent run:

Architecture & Behaviors:
- Output Directory: `./sentinel-reports/`
- Filename Schema:  `sentinel-<agentId>-<ISO-timestamp>.txt`
- Write Strategy:   Synchronous, unbuffered atomic appends (`fs.appendFileSync`).
- Data Capture:
  - Session metadata (ID, active agent persona, workspace path, start time).
  - Full conversation turns between user and agent personas.
  - Event triggers (slash commands, file inspections, config updates).
  - Complete security scan records (findings, CWEs, CVSS, cURLs, Git diffs).
  - Session duration and termination timestamp.
